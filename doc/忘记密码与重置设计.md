# 📖 忘记密码与重置密码设计文档

## 一、 功能概述

当用户遗忘其打卡助手的登录密码时，系统需要提供一套安全、自助的密码重置闭环流程。本功能主要包括：
1. 登录弹窗上新增 **“忘记密码”** 入口，引导用户提交注册邮箱。
2. 后端生成高强度的单次重置 Token 并关联写入数据库，同时向用户邮箱发送带有重置链接的系统邮件。
3. 用户点击邮件中的链接跳转至专用重置页面，设定新密码并保存，实现自助找回。

---

## 二、 安全设计原则 (Security Guidelines)

为了防范恶意扫描、撞库或任意密码修改漏洞，本设计遵循以下安全规范：

1. **防账号探测 (Prevent Account Enumeration)**：
   - 当用户在第一步提交重置请求时，无论该邮箱是否已在系统中注册，接口响应均统一返回：`{"code":0, "message":"重置链接已发送至您的邮箱，请注意查收"}`。
   - 这样可以防止恶意攻击者利用该接口探测任意邮箱在平台上的注册情况。
2. **Token 安全度与时效限制**：
   - 重置 Token 必须使用加密安全的随机发生器（如 Node.js 的 `crypto.randomBytes(32)`）生成，不可预测。
   - 设定严格的有效期限制，默认为 **1 小时**。过期直接失效。
3. **单次使用约束 (One-time Use)**：
   - 每个重置 Token 在成功重置一次密码后，必须立刻在数据库中予以**物理销毁/标记失效**，不得重复使用。
4. **频率限制 (Rate Limiting)**：
   - 限制单个邮箱在短时间（如 1 分钟内）只能请求 1 次重置邮件，24 小时内最多请求 5 次，防范恶意调用短信/邮件网关进行垃圾邮件轰炸。

## 三、 数据库设计扩展 (Prisma)

为解耦核心 `User` 模型，建议采用单独的 `PasswordResetToken` 数据表来存储和校验临时凭证。

```prisma
// 在 prisma/schema.prisma 中追加如下定义：

model PasswordResetToken {
  id        String   @id @default(cuid())
  email     String   @db.VarChar(191)
  token     String   @unique @db.VarChar(255)
  expiresAt DateTime // 过期时间戳 (createdAt + 1小时)
  createdAt DateTime @default(now())

  @@index([email])
  @@index([token])
}
```

## 四、 后端 API 接口设计

### 1. 发起密码重置请求
* **Endpoint**：`POST /api/auth/forgot-password`
* **Request Body**：
  ```json
  {
    "email": "user@example.com"
  }
  ```
* **后端处理步骤**：
  1. 校验邮箱字段格式。
  2. 生成 64 位的安全随机 Token（`crypto.randomBytes(32).toString('hex')`）。
  3. 计算过期时间为 `Date.now() + 3600000`（1小时）。
  4. 写入 `PasswordResetToken` 数据表。
  5. 异步调用邮件服务（如 `Nodemailer`、`Resend` 等）向目标邮箱发送包含重置链接的邮件：
     `http://localhost:3000/zh-CN/reset-password?token=xxxxxx`
  6. 返回成功消息（不暴露该邮箱是否存在）。

---

### 2. 校验 Token 并保存新密码
* **Endpoint**：`POST /api/auth/reset-password`
* **Request Body**：
  ```json
  {
    "token": "xxxxxx",
    "password": "new_password_123"
  }
  ```
* **后端处理步骤**：
  1. 根据 `token` 在 `PasswordResetToken` 表中查询记录。
  2. 若记录不存在，或当前时间已超过 `expiresAt`，返回 `400` 错误：“重置链接已失效，请重新发起申请”。
  3. 校验新密码长度（8～128个字符）。
  4. 调用 `hashPassword()` 对新密码进行加密，得到新密码哈希。
  5. 在 `User` 表中，根据 Token 关联的 `email` 字段更新该用户的 `passwordHash`。
  6. **核心安全步骤**：从 `PasswordResetToken` 表中删除该 Token，确保其不能被二次使用。
  7. 返回重置成功报文。

## 五、 前端 UI 与页面设计

### 1. 登录弹窗 (AuthModal) 的状态流转
- 在 `modalMode === 'login'` 下，输入密码栏的右下方新增一处 **“忘记密码？”** 的灰色轻量链接。
- 点击后，调用 `setModalMode('forgotPassword')` 切换当前弹窗表单状态。
- `forgotPassword` 状态下仅展示一个邮箱输入框与“发送重置邮件”的提交按钮，点击发送后，捕获 API 状态并展示成功 Alert。

## 六、 邮件驱动接入方案 (SMTP / API)

上线时，后端发送邮件主要有两种主流免费/低成本对接方案：

### 方案 A：使用 `nodemailer` 直连常用 SMTP 发信服务器
- **适用场景**：本地开发测试、小规模使用。
- **配置参数**：
  ```env
  SMTP_HOST="smtp.qq.com"  # 或 smtp.163.com / smtp.gmail.com
  SMTP_PORT=465
  SMTP_USER="your-email@qq.com"
  SMTP_PASS="授权码或应用密码"
  ```

### 方案 B：使用第三方专业发信网关 (如 Resend.com) - 🌟 生产推荐
- **适用场景**：生产环境、追求极高的送达率和邮件格式漂亮排版。
- **优点**：每个月有大量的免费发信额度，提供极简的 JS SDK，支持使用 React 编写漂亮 HTML 邮件模板。
- **配置参数**：
  ```env
  RESEND_API_KEY="re_xxxxxxxxxxxxxx"
  ```
