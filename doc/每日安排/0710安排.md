**日期**：2026-07-10

## 一、明日核心目标

明天的重点不再是大幅扩展功能，而是继续做三件事：

1. 收页面层剩余改动点  
2. 补完整登录态端到端验收  
3. 把 Prompt 相关主链路从“基本可用”推进到“完整验收通过”  

---

## 二、任务安排

### 1. 合并并核对页面层改动

- 接收并检查页面改动点
- 重点核对：
  - Prompt 设置页
  - 创建页
  - 用户设置页
  - 边界提示区样式与文案
- 确认页面改动没有破坏今天已经稳定下来的边界规则

### 2. 跑完整登录态端到端主链路

按真实用户路径完成一轮本地验收：

- 登录
- 进入 Prompt 设置页
- 新建 / 编辑 / 启停模板
- 修改 persona 并保存
- 进入创建页选择模板
- 上传图片并生成
- 重新生成文案
- 查看历史记录
- 查看日历统计
- 查看首页统计

目标不是只证明“页面能点”，而是确认数据口径、生成逻辑和页面表现都一致。

### 3. 补一轮边界回归

在页面层改动合入后，再快速回归以下关键边界：

- persona `800 / 801`
- 模板内容 `2400 / 2401`
- 测试输入 `500 / 501`
- 创建页输入 `500 / 501`
- 图片数量提示与真实生成传参的一致性

### 4. 处理阻塞问题

如果明天验收过程中出现问题，优先级按下面处理：

- `P0` 直接阻塞主链路的问题
- `P1` 边界规则和接口不一致的问题
- `P2` 页面视觉或体验微瑕疵

保持小步修复，不做与主线无关的大范围重构。

### 5. 质量检查与记录

收尾时执行：

```text
npm run typecheck
npm run lint
npm run build
```

并将明天的验收结果、阻塞项、修复项写入 `0710日报.md`。
