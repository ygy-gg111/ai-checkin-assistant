# 部署方案（Deployment Plan）

## 一、推荐部署方案

MVP 阶段推荐使用：

```text
GitHub + Vercel + 云数据库 + 对象存储
```

整体架构：

```text
本地开发
   │
   ▼
GitHub 仓库
   │
   ▼
Vercel 自动部署
   │
   ├── Next.js 页面
   ├── API Routes
   └── OpenAI API 调用
   │
   ▼
云数据库 MySQL
   │
   ▼
对象存储 OSS / R2
```

该方案适合第一阶段快速上线，避免一开始就维护云服务器、Nginx、PM2、Docker 等复杂环境。

------

## 二、为什么选择 Vercel

Vercel 是 Next.js 官方团队推出的部署平台，非常适合部署 Next.js 项目。

选择 Vercel 的原因：

- 支持 Next.js App Router
- 支持 API Routes
- 支持 Server Actions
- 支持环境变量配置
- 支持 GitHub 自动部署
- 支持 HTTPS
- 部署流程简单
- 不需要自己维护服务器

对于当前项目来说，Vercel 可以直接运行：

- 前端页面
- API 接口
- AI 调用逻辑

------

## 三、部署流程

### 1. 本地开发

本地完成项目开发：

```bash
npm run dev
```

访问：

```text
http://localhost:3000
```

------

### 2. 上传 GitHub

初始化 Git：

```bash
git init
git add .
git commit -m "feat: init ai checkin project"
```

关联远程仓库：

```bash
git remote add origin https://github.com/yourname/ai-checkin.git
git push -u origin main
```

------

### 3. Vercel 导入项目

进入 Vercel 后：

```text
New Project
    ↓
Import Git Repository
    ↓
选择 ai-checkin
    ↓
Deploy
```

Vercel 会自动执行：

```bash
npm install
npm run build
npm run start
```

部署完成后，会生成一个线上地址：

```text
https://ai-checkin.vercel.app
```

------

## 四、环境变量配置

在 Vercel 项目设置中配置环境变量。

必须配置：

```env
DATABASE_URL="mysql://user:password@host:3306/ai_checkin"

OPENAI_API_KEY="sk-xxx"
OPENAI_MODEL="gpt-4o-mini"

JWT_SECRET="your-secret"

STORAGE_PROVIDER="r2"
STORAGE_BUCKET="xxx"
STORAGE_ACCESS_KEY="xxx"
STORAGE_SECRET_KEY="xxx"
```

本地开发使用：

```text
.env.local
```

线上环境使用：

```text
Vercel Environment Variables
```

注意：

```text
.env.local 不要提交到 GitHub
```

## 五、数据库部署

MVP 阶段推荐使用云数据库。

可选方案：

```text
PlanetScale
Railway
Supabase
阿里云 RDS
腾讯云数据库 MySQL
```

如果想国内访问稳定，可以选择：

```text
腾讯云数据库 MySQL
阿里云 RDS
```

数据库只需要提供一个连接字符串：

```env
DATABASE_URL="mysql://user:password@host:3306/ai_checkin"
```

Prisma 通过该连接字符串访问数据库。

## 六、图片存储方案

开发阶段可以使用本地目录：

```text
/uploads
```

但上线后不建议使用 Vercel 本地存储。

原因：

- Vercel 文件系统不适合长期保存用户上传图片
- 重新部署后本地文件可能丢失
- 图片访问和扩展能力较弱

生产环境推荐使用对象存储：

```text
Cloudflare R2
阿里云 OSS
腾讯云 COS
Amazon S3
```

推荐优先级：

```text
国内项目：阿里云 OSS / 腾讯云 COS
海外项目：Cloudflare R2
```

------

## 七、GitHub 自动部署

Vercel 连接 GitHub 后，每次执行：

```bash
git push
```

Vercel 都会自动：

```text
拉取最新代码
    ↓
安装依赖
    ↓
构建项目
    ↓
发布新版本
```

也就是说：

```text
本地改代码
    ↓
提交到 GitHub
    ↓
Vercel 自动上线
```

无需手动登录服务器。

------

## 八、云服务器部署方案（后期）

如果后续项目需要：

- Python AI 服务
- 本地大模型
- OCR
- 视频分析
- Docker
- GPU
- 更强的后端控制能力

可以迁移到云服务器。

云服务器架构：

```text
云服务器
   │
   ├── Nginx
   ├── Next.js
   ├── PM2
   ├── MySQL
   ├── Redis（后期）
   └── Python AI Service（后期）
```

部署方式：

```bash
npm install
npm run build
pm2 start npm --name ai-checkin -- start
```

Nginx 反向代理：

```text
80 / 443
   ↓
localhost:3000
```

------

## 九、Docker 部署方案（后期）

当项目增加多个服务后，可以使用 Docker Compose。

例如：

```text
docker-compose.yml

services:
  web:
    Next.js

  mysql:
    MySQL

  redis:
    Redis

  ai:
    Python FastAPI
```

适合后期架构：

```text
Next.js
   ↓
Python AI Service
   ↓
本地模型 / GPU
```

MVP 阶段不建议一开始使用 Docker，避免增加复杂度。

## 十、最终推荐路线

### 第一阶段：MVP

推荐：

```text
GitHub + Vercel + 云数据库 + 对象存储
```

目标：

- 快速上线
- 快速验证产品
- 不维护服务器

------

### 第二阶段：正式运营

可选择：

```text
Vercel + 云数据库 + OSS
```

或者：

```text
云服务器 + Nginx + PM2 + MySQL
```

------

### 第三阶段：AI 能力增强

当需要本地模型时，迁移到：

```text
云服务器 / GPU 服务器 + Docker + Python AI Service
```

------

## 十一、当前建议

当前项目第一版只使用：

```text
Next.js + OpenAI API
```

因此最推荐：

```text
GitHub + Vercel
```

数据库使用云 MySQL，图片使用对象存储。

这样可以最快完成上线，不被服务器部署、环境配置和运维问题拖慢进度。
