- 系统架构（System Architecture）

  ## 一、整体架构

  第一阶段（MVP）采用 **单体应用（Monolith）架构**，整个系统仅包含一个 Next.js 应用，通过 API Routes 提供业务接口，并统一调用 AI Provider 完成图片分析和文案生成。

  整体架构如下：

  ```text
                                  用户（User）
                                       │
                                       │
                                       ▼
                           ┌──────────────────────┐
                           │      Next.js App     │
                           │                      │
                           │  页面（App Router）   │
                           │  API Routes          │
                           │  Server Actions      │
                           └──────────┬───────────┘
                                      │
              ┌───────────────────────┼────────────────────────┐
              │                       │                        │
              ▼                       ▼                        ▼
     ┌────────────────┐     ┌────────────────┐      ┌────────────────┐
     │   Prisma ORM   │     │   AI Provider  │      │ Storage Service│
     │                │     │                │      │                │
     │ MySQL Database │     │ OpenAI GPT-4o  │      │ Local Uploads  │
     │                │     │ (Vision+Text)  │      │ (后续 OSS/R2)   │
     └────────────────┘     └────────────────┘      └────────────────┘
  ```
  
  ------
  
  # 二、整体数据流

  ```text
  用户上传图片

          ▼

  保存图片         查询 Prompt 模板
          │              │
          └──────┬───────┘
                 ▼

                 ▼
  ```

  ------

  # 三、系统模块
  
  整个系统划分为四个核心模块：
  
  ```text
  Next.js Application
  │
  ├── Web UI（页面）
  │
  ├── API Routes（业务接口）
  │
  ├── AI Provider（AI能力）
  │
  ├── Database（数据库）
  │
  └── Storage（图片存储）
  ```
  
  ------
  
  ## 1、Web UI
  
  负责所有用户交互。
  
  主要功能：
  
  - 上传图片
  - 输入今日描述
  - 查看 AI 生成结果
  - 一键复制
  - 查看历史记录
  
  Web 层不直接调用 AI。

  所有请求统一交给 API Routes。

  ------

  ## 2、API Routes

  API Routes 是整个系统的业务中心。
  
  负责：
  
  - 参数校验
  - 图片上传
  - Prompt 拼接
  - 调用 AI Provider
  - 保存数据库
  - 返回生成结果
  
  API Routes 不关心底层 AI 使用哪种模型。
  
  所有 AI 调用统一交由 AI Provider 完成。
  
  ------
  
  ## 3、AI Provider
  
  AI Provider 是整个 AI 能力的统一入口。
  
  当前默认使用：
  
  ```text
  OpenAI GPT-4o mini
  ```
  
  负责：
  
  - 图片理解
  - 文案生成
  - 标签推荐
  
  后续可无缝扩展：
  
  ```text
  AI Provider
  
  ├── OpenAI
  ├── Gemini
  ├── Claude
  ├── Qwen
  └── Local（预留）
  ```
  
  业务层始终调用统一接口，而无需关心具体模型。
  
  ------
  
  ## 4、Database
  
  采用：
  
  ```text
  MySQL
  +
  Prisma ORM
  ```
  
  负责存储：
  
  - 用户信息
  - 打卡记录
  - 图片地址
  - AI 生成结果
  - Prompt 模板
  
  所有数据库访问统一通过 Prisma 完成。
  
  ------
  
  ## 5、Storage
  
  MVP 阶段采用本地存储：
  
  ```text
  /uploads
  ```
  
  后续可切换：
  
  - 阿里云 OSS
  - 腾讯云 COS
  - Cloudflare R2
  - Amazon S3

  业务代码无需修改。

  # 六、架构特点
  
  本项目采用**单体应用 + Provider 模式**，具有以下优势：
  
  - **开发简单**：只有一个 Next.js 项目，无需维护多个服务。
  - **维护成本低**：页面、接口、数据库统一管理。
  - **AI 解耦**：AI 能力通过 Provider 封装，可随时切换模型。
  - **扩展性强**：未来可新增 Gemini、Claude、本地模型，而无需修改业务逻辑。
  - **平滑演进**：当需要 OCR、视频分析、本地模型时，可新增 Python AI 服务作为新的 Provider，不影响现有架构。
  
  因此，第一阶段专注于快速完成 MVP，后续根据产品发展逐步扩展 AI 能力，而不是一开始构建复杂的多服务架构。
